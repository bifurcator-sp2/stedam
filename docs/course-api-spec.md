# API курсов — контракт обмена (для фронтенда)

> Источник правды: `docs/course-domain-spec.md` (домен и правила).
> Этот документ описывает **только HTTP-контракт**: маршруты, форматы
> запросов, ответов и ошибок. При расхождении с кодом — править оба.

Базовый префикс: `/api`. Аутентификация: `auth:sanctum` (cookie-сессия или
Bearer-токен), все маршруты ниже требуют авторизации, кроме явно помеченных.

---

## 0. Общие соглашения

### 0.1. Формат ответа

Все ответы — JSON, `Content-Type: application/json`.

- Успех — `200` / `201`, тело по схеме метода.
- Ошибка валидации — `422`, тело Laravel-стандарта:

```json
{
  "message": "The given data was invalid.",
  "errors": {
    "title": ["Поле title обязательно."]
  }
}
```

- Доменные ошибки — см. §0.5 (единый обработчик).

### 0.2. Пагинация

Листинг возвращает объект с `data` и `meta`:

```json
{
  "data": [ /* элементы */ ],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 137,
    "last_page": 7
  }
}
```

Query-параметры: `page` (1-based), `per_page` (1..100, по умолчанию 20).

### 0.3. Разрешение пользователя в контекст

Контекст смотрящего (`CourseViewerContext`) собирается из текущего пользователя
и его ролей. Роль выбирается по приоритету (высшая выигрывает):

`admin` > `methodologist` > `headteacher` > `teacher` > `parent` > `student`.

Гость — только для неавторизованных (в текущем API не используется,
все маршруты под `auth:sanctum`).

### 0.4. Даты и числа

- Даты — ISO-8601 с таймзоной: `2025-01-15T10:30:00+00:00`.
- Пороги, оценки, пройденность — десятичные дроби в диапазоне `0..1`
  (например `0.6`), НЕ проценты.
- `time_gap` — **целые часы** (не минуты).

### 0.5. Коды ошибок домена

| HTTP | Исключение | `code` в теле | Когда |
|------|-----------|---------------|-------|
| 403 | `CourseAccessDenied` | `course_access_denied` | нет прав на операцию |
| 404 | `CourseNotFound` | `course_not_found` | курс/назначение не найдено |
| 404 | `CourseThemeNotFound` | `course_theme_not_found` | темы нет в курсе |
| 404 | `CourseLessonNotInTheme` | `course_lesson_not_in_theme` | урока нет в теме |
| 409 | `CourseAlreadyAssigned` | `course_already_assigned` | повторное назначение |
| 422 | `CourseLocaleChangeDenied` | `course_locale_change_denied` | смена locale у курса с уроками |
| 422 | `CourseTaxonomyChangeDenied` | `course_taxonomy_change_denied` | смена таксономии у непустого курса |
| 422 | `InvalidCourseOrder` | `invalid_course_order` | дубль/неположительный order |
| 422 | `InvalidCourseGrade` | `invalid_course_grade` | оценка вне `0..1` |
| 422 | `InvalidCompletion` | `invalid_completion` | пройденность вне `0..1` |
| 422 | `InvalidNextLessonThreshold` | `invalid_next_lesson_threshold` | порог не в `(0..1]` |
| 422 | `InvalidTimeGap` | `invalid_time_gap` | отрицательный разрыв |

Единый формат тела ошибки:

```json
{
  "message": "You are not allowed to edit course 12",
  "code": "course_access_denied",
  "course_id": 12
}
```

> `course_id` присутствует не всегда — только там, где он есть в исключении.

## 1. Объекты (схемы ответов)

### 1.1. `Course` (полный, с составом)

```json
{
  "id": 12,
  "user_id": 7,
  "is_system": false,
  "title": "Основы Python",
  "description": "Курс для 8 класса",
  "locale": "ru",
  "next_lesson_threshold": 0.6,
  "tax_id": 31,
  "updated_at": "2025-01-15T10:30:00+00:00",
  "lessons_count": 7,
  "themes": [
    {
      "id": 88,
      "title": "Введение",
      "order": 1,
      "lessons": [
        {
          "lesson_id": 101,
          "order": 1,
          "type_id": 2,
          "time_gap": 2
        }
      ]
    }
  ]
}
```

| Поле | Тип | Смысл |
|------|-----|-------|
| `id` | int | id курса |
| `user_id` | int \| null | автор; `null` — **системный курс** |
| `is_system` | bool | дубль-флаг `user_id === null` (удобно фронту) |
| `title` | string | название |
| `description` | string | описание |
| `locale` | string | `ru` / `en` / ... |
| `next_lesson_threshold` | float | порог допуска к следующему уроку `(0..1]` |
| `tax_id` | int \| null | узел таксономии |
| `updated_at` | string \| null | ISO-8601 |
| `lessons_count` | int | всего уроков в курсе |
| `themes` | array | пустой — если запрос без состава |

Состав (`themes`) отдаётся **по умолчанию** в `GET /courses/{id}` и
**не отдаётся** в листинге (см. 1.2).

### 1.2. `CourseListItem` (элемент листинга)

```json
{
  "id": 12,
  "user_id": 7,
  "is_system": false,
  "title": "Основы Python",
  "description": "Курс для 8 класса",
  "locale": "ru",
  "tax_id": 31,
  "lessons_count": 7,
  "updated_at": "2025-01-15T10:30:00+00:00"
}
```

Без `themes`. `lessons_count` может отсутствовать, если не запрашивали
count — фронт должен терпеть `null`.

### 1.3. `CourseAssignment`

```json
{
  "id": 555,
  "course_id": 12,
  "student_id": 42,
  "assigned_by": 7,
  "completion": 0.35,
  "grade": 0.72,
  "created_at": "2025-01-15T10:30:00+00:00"
}
```

| Поле | Тип | Смысл |
|------|-----|-------|
| `completion` | float | пройденность `0..1` |
| `grade` | float | средняя оценка `0..1`. **`0` — валидная оценка**, не пустая |

### 1.4. `CoursePermissions` (вложен в детальный курс)

Чтобы фронт не дублировал логику прав, `GET /courses/{id}` отдаёт блок `can`:

```json
{
  "can": {
    "edit": true,
    "delete": true,
    "assign": true,
    "see_progress": true
  }
}
```

## 2. Маршруты

### 2.1. Листинг курсов

```
GET /api/courses
```

Права: scope определяется ролью (§13.2):
`student` — назначенные ему; `teacher` — свои + системные;
`methodologist` / `headteacher` / `admin` — все; `parent` — не видит каталог.

Query:

| Параметр | Тип | Описание |
|----------|-----|----------|
| `tax_id` | int, optional | узел таксономии (с потомками) |
| `search` | string, optional | поиск по названию/описанию |
| `page` | int | страница |
| `per_page` | int | размер, 1..100 |

Ответ `200`:

```json
{
  "data": [ /* CourseListItem[] */ ],
  "meta": { "current_page": 1, "per_page": 20, "total": 137, "last_page": 7 }
}
```

---

### 2.2. Детальный курс

```
GET /api/courses/{course_id}
```

Права: курс должен быть виден смотрящему (`CourseAccessDenied` → 403,
если не виден; `CourseNotFound` → 404, если нет).

Ответ `200`: полный `Course` (§1.1) + `can` (§1.4).

---

### 2.3. Создание курса

```
POST /api/courses
```

Права: `canCreate` (§13.1) — обычный курс создаётся **только себе**,
системный (`user_id = null`) — **только `admin`**.

Тело:

```json
{
  "title": "Основы Python",
  "description": "Курс для 8 класса",
  "locale": "ru",
  "next_lesson_threshold": 0.6,
  "tax_id": 31,
  "user_id": null
}
```

| Поле | Обяз. | Правила |
|------|-------|---------|
| `title` | да | string, 1..255 |
| `description` | да | string, 1..5000 |
| `locale` | да | string, 2..10, входит в `config('course.locales')` |
| `next_lesson_threshold` | да | number > 0, ≤ 1 |
| `tax_id` | нет | int, существует в таксономии |
| `user_id` | нет | int \| null; **опускать = создать себе**; `null` = системный (только admin) |

Ответ `201`: полный `Course` (темы пустые — состав добавляется на
сохранённом курсе, см. 2.6).

Ошибки: `403 course_access_denied` (попытка создать системный без прав).

---

### 2.4. Редактирование шапки

```
PATCH /api/courses/{course_id}
```

Права: `canEdit` — только автор курса; системный — только `admin`.

Тело (все поля необязательные; отсутствие = «не менять»):

```json
{
  "title": "Новое название",
  "description": "Новое описание",
  "locale": "en",
  "next_lesson_threshold": 0.7,
  "tax_id": 42
}
```

| Поле | Правила |
|------|---------|
| `title` | string, 1..255 |
| `description` | string, 1..5000 |
| `locale` | смена запрещена, если в курсе есть уроки → `422 course_locale_change_denied` |
| `next_lesson_threshold` | number > 0, ≤ 1 |
| `tax_id` | смена запрещена у непустого курса → `422 course_taxonomy_change_denied`; уроки должны лежать в целевой ветке |

Ответ `200`: полный `Course`.

> **Различие «не менять» и «очистить»**: `tax_id: null` — явная попытка
> убрать таксономию (сработает проверка домена). Чтобы «не менять» —
> просто не передавайте ключ.

---

### 2.5. Удаление курса

```
DELETE /api/courses/{course_id}
```

Права: `canEdit` (только автор; системный — только `admin`).

Удаляет курс вместе со всеми назначениями. Для каждого назначения
публикуется `CourseAssignmentRemoved` → слушатель стирает **не начатые**
прохождения уроков (начатые остаются).

Ответ `204`: пустое тело.

---

### 2.6. Темы курса

Темы — часть агрегата `Course`. Каждая операция возвращает **полный
обновлённый курс** — фронт перерисовывает редактор из ответа.

#### 2.6.1. Добавить тему

```
POST /api/courses/{course_id}/themes
```

Права: `canEdit`.

```json
{ "title": "Введение" }
```

Ответ `201`: полный `Course`.

#### 2.6.2. Переименовать тему

```
PATCH /api/courses/{course_id}/themes/{theme_id}
```

```json
{ "title": "Новое название темы" }
```

Ответ `200`: полный `Course`.

#### 2.6.3. Удалить тему

```
DELETE /api/courses/{course_id}/themes/{theme_id}
```

Ответ `200`: полный `Course` (удаление темы меняет состав → пересчёт).

#### 2.6.4. Переставить тему

```
PUT /api/courses/{course_id}/themes/{theme_id}/position
```

```json
{ "position": 1 }
```

`position` — 1-based целевая позиция. Остальные темы сдвигаются
(двухфазная нормализация `order`).

Ответ `200`: полный `Course`.

---

### 2.7. Уроки в теме

#### 2.7.1. Добавить урок в тему

```
POST /api/courses/{course_id}/themes/{theme_id}/lessons
```

Права: `canEdit`.

```json
{
  "lesson_id": 101,
  "type_id": 2,
  "time_gap": 2
}
```

| Поле | Обяз. | Описание |
|------|-------|----------|
| `lesson_id` | да | int, урок должен существовать (иначе `404 course_lesson_not_in_theme`) |
| `type_id` | нет | тип урока из справочника `lesson_types` |
| `time_gap` | нет | целые часы, ≥ 0 |

> Один урок нельзя добавить в две темы одного курса —
> `422 invalid_course_order` (нарушение уникальности `lesson_id` в курсе).

Ответ `201`: полный `Course`.

#### 2.7.2. Убрать урок из темы

```
DELETE /api/courses/{course_id}/themes/{theme_id}/lessons/{lesson_id}
```

Ответ `200`: полный `Course`.

#### 2.7.3. Переставить урок

```
PUT /api/courses/{course_id}/themes/{theme_id}/lessons/{lesson_id}/position
```

```json
{ "position": 2 }
```

Ответ `200`: полный `Course`.

#### 2.7.4. Сменить тип урока

```
PATCH /api/courses/{course_id}/themes/{theme_id}/lessons/{lesson_id}/type
```

```json
{ "type_id": 3 }
```

`type_id: null` — снять тип.

Ответ `200`: полный `Course`.

#### 2.7.5. Сменить разрыв (time_gap)

```
PATCH /api/courses/{course_id}/themes/{theme_id}/lessons/{lesson_id}/time-gap
```

```json
{ "time_gap": 24 }
```

Целые часы, ≥ 0. Ответ `200`: полный `Course`.

---

### 2.8. Назначения

#### 2.8.1. Список назначений курса

```
GET /api/courses/{course_id}/assignments
```

Права: `canEdit` (видит автор) ИЛИ роль с доступом к прогрессу.

Ответ `200`: `CourseAssignment[]` (§1.3), без пагинации (курс редко
имеет тысячи учеников; если понадобится — добавим).

#### 2.8.2. Назначить курс ученику

```
POST /api/courses/{course_id}/assignments
```

Права: `canAssign` (роль ≥ teacher, курс виден).

```json
{ "student_id": 42 }
```

Внутри транзакции: назначение + событие `CourseAssignmentCreated` →
слушатель создаёт прохождения уроков (первый — `scheduled` на `now`).

Ответ `201`: `CourseAssignment`.

Ошибки: `409 course_already_assigned` — пара (курс, ученик) уже есть.

#### 2.8.3. Снять назначение

```
DELETE /api/courses/{course_id}/assignments/{student_id}
```

`student_id` — id ученика, не id назначения (назначение однозначно
определяется парой курс+ученик).

Слушатель удаляет **не начатые** прохождения (для начатых и завершённых
не трогает ничего — правила `LearnRepository::deleteUnstarted`).

Ответ `204`: пустое тело.

---

### 2.9. Пересчёт прогресса

#### 2.9.1. Пересчитать по одному ученику

```
POST /api/courses/{course_id}/assignments/{student_id}/recalculate
```

Права: `canEdit` ИЛИ `canSeeProgressOf(student_id)`.

Ответ `200`: обновлённый `CourseAssignment`.

#### 2.9.2. Пересчитать по всем ученикам

```
POST /api/courses/{course_id}/recalculate
```

Права: `canEdit` (автор) ИЛИ роль со «всё» (admin/methodologist).

Ответ `200`: пересчёт выполнен синхронно, в теле — число
пересчитанных назначений.

```json
{ "processed": 137 }
```

> `202 {message: "Recalculation scheduled"}` здесь не используется:
> задача выполняется до ответа, и `202` вводил бы клиента в заблуждение.
> Если пересчёт уедет в очередь, контракт вернётся к `202`.

## 3. Матрица прав (сводка для UI)

Чтобы фронт не показывал кнопки, которые дадут 403:

| Роль | Список | Создать свой | Создать системный | Редактировать | Удалить | Назначить | Прогресс ученика |
|------|--------|--------------|-------------------|---------------|---------|-----------|------------------|
| `student` | назначенные | — | — | — | — | — | свой |
| `teacher` | свои + системные | да (себе) | — | свои | свои | да | своих учеников |
| `methodologist` | все | да (себе) | — | свои | свои | да | всех |
| `headteacher` | все | да (себе) | — | свои | свои | да | всех |
| `admin` | все | да (себе) | **да** | свои + системные | свои + системные | да | всех |
| `parent` | назначенные детям | — | — | — | — | — | детей |

Ключевое: «вижу все» ≠ «правлю все». Управлять курсом может **только
его автор** (или `admin` для системных).

Системные курсы (`user_id = null`): `student` и `parent` видят их только
при назначении — и в списке, и в детальном GET. Без назначения системный
курс для них закрыт (`403 course_access_denied`), хотя `teacher`/`guest`
видят системные всегда.

## 4. Типовые сценарии фронта

### 4.1. Редактор курса

1. `GET /courses/{id}` — полный курс + `can`.
2. Добавление темы → `POST .../themes` → ответ = новый полный курс,
   заменяем состояние целиком.
3. Все мутации состава возвращают полный `Course`. Фронт может не
   применять локальные патчи — просто подставляет ответ. Это дороже по
   трафику, но исключает рассинхрон.

### 4.2. Назначение курса классу

Фронт сам перебирает учеников и вызывает `POST .../assignments` на каждого.
Батч-эндпоинта сейчас нет. 409 на уже назначенного — норм, можно
молча пропускать (или не слать дубли).

### 4.3. Отображение системного курса

`is_system: true` → бейдж «Системный», кнопка «Редактировать» видна
только `admin`.

## 5. Чего в API НЕТ (и почему)

| Что | Почему | Что делать фронту |
|-----|--------|-------------------|
| Массовое назначение (batch) | нет Action | цикл запросов |
| Состав курса через одну мутацию (diff) | операции атомарны по теме/уроку | последовательные запросы |
| Публикация / черновик курса | в домене нет состояния публикации | — |
| Копирование курса | нет Action | — |
| Список доступных уроков для добавления | это контекст Lessons | `GET /api/lessons/...` из Learn/Lessons API |
| Настройка адаптивности | в домене нет | — |

## 6. Открытые вопросы к реализации

1. **`RecalculateCourseForAllAction`** — решено: синхронный, `200`
   `{processed: N}` (см. 2.9.2).
2. **`GET /courses/{id}` проверка видимости** — решено: `canView()` в
   `CourseViewerContext` плюс проверка назначения в контроллере
   (`assertCanView`). Системный курс student/parent открывает только при
   назначении.
3. **`lessons_count` в листинге** — считать `withCount` (N+1-safe) или
   не отдавать вовсе? Предлагаю отдавать.
4. **`permissions` в листинге** — только в детальном курсе (как сейчас
   описано) или и в списке? Предлагаю только в детальном: список длинный.
